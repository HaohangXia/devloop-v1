# DevLoop · 工人须知

一个 Python 工具包，用来编排 AI 编码智能体：**并行 + 隔离 + 脚本裁决完成 + 人在环**。

> ⛔ 2026-08-15 起**跳过便宜模型**（D-COST-01）：工人走订阅（opus），**跟编排方同一个额度池** —— ⚠️ 派单**不省额度，是多花**。⭐ 它剩下的理由只有三个：**并行 · 隔离 · 无人值守**。
你在 `--bare` 模式下运行，**读不到项目的其它文档**，本文件是你唯一的规则来源。

## 铁律（违反即判失败）

1. **不许改测试来让自己过关。** 已有的测试文件一个字都不许动——测试是判定标准，改判定标准不算通过。
   ⭐ **但你可以、也应该为自己写的功能补测试**：新建 `tests/test_<名字>.py`，闸会放行。
   ⛔ 只许新建 `test_*.py`。别新建 `conftest.py` 或改已有文件——一个 autouse fixture
   就能架空整包已有断言，闸会当作弊拦下。要动已有测试，在报告里说明理由，交给人来改。
2. **失败必须能被区分。** 本项目的核心约定是「活没干好」（退出码 1）与「工具坏了」（退出码 2）必须分开。写错误处理时保持这个区分，不要把两者合并成一个失败。
3. **不许静默降级。** 找不到配置、缺少文件、参数非法时**报错退出**，不要退回默认值继续跑。理由：静默降级会让人以为在用 A、实际在用 B，排查时找不到线索。
4. **不许把密钥写进日志或 repr。** `WorkerConfig.auth_token` 已标 `repr=False`，新增涉及密钥的字段时照做。

## 禁改清单

- `tests/` —— **已有**文件（新建 `test_*.py` 允许；新建其它文件不允许）
- `.devloop/` —— 任何文件
- `pyproject.toml` 的 `[project]` 段（依赖与版本）

## 代码约定

- Python 3.11+，类型注解写在函数签名上
- 注释解释**为什么**，不复述代码在做什么；**每条约束尽量附上它的由来**（本项目的注释大量记录了实测教训，这是有意的）
- 中文注释与文档字符串，与现有风格一致

## 常用命令

```bash
# 跑全部测试（基线：33 个测试 / 0.24 秒）
python -m pytest -q

# 只跑某个文件
python -m pytest tests/test_models.py -q

# 语法检查
python -c "import devloop.cli"
```

## 输出纪律

- 关于代码现状的结论**必须附出处**：`文件路径::符号名`（例如 `devloop/gates.py::find_bash`）
- ⛔ 不要用行号做锚点——行号会随改动漂移
- 不确定的事说不确定，不要猜
