git worktree 里干活，改动完成后会有一组闸自动裁决。

# 任务

**BACKLOG G-126**：这个项目里有一批守卫**只做过红检、没做过绿检**。

- **红检** = 故意弄坏 → 守卫必须报警
- **绿检** = 什么都不改 → 守卫必须是绿的

⛔ **只做过红检的守卫，可能对任何输入都报警 —— 和一根坏掉的火警没区别。**

**这一单只干两件事，⛔ 别扩张**：

### 一、点名（**这一半是主产物**）

扫 `tests/` 下全部测试，找出**只验了「坏的时候会红」、没验「好的时候是绿的」**的那些。

⭐ 判据自己想清楚并在报告里写明 —— 比如：
一条测试只有 `pytest.raises` / 只断言「必须报错」，
而**同一个被测对象在正常输入下的行为一条都没断言**。

⚠️ ⛔ **这一步不许用「文件名里有没有『红检』二字」这类代用品。**

产出：一张表，**每条带文件名 + 测试名 + 为什么判它缺绿检**。

### 二、补最要紧的 **3 条**（⛔ 不许多补）

从表里挑**最要紧的 3 条**（挑的理由写出来），给它们补上绿检。
⚠️ ⛔ **不许一口气补几十条** —— 这一单的价值在「点名」，补是顺带证明点名是对的。

# 改动范围

- 新建 `tests/test_green_check_coverage.py`（放那张表的机械判据，如果你做得出来）
- ⭐ 最多**再动 3 个**已有测试文件（就是你挑的那 3 条所在的文件）

# 自己验

- `python -m pytest -q`（**必须全绿**）
- ⭐ 对你补的那 3 条各做一次红检：把被测对象弄坏 → 确认变红；还原 → 确认回绿。
  三次的输出都贴。

- ⛔ 不许新建 `tests/conftest.py`
- ⛔ 不许改 `.devloop/` 下任何文件
- ⛔ 不许 git commit / push
- ⛔ **不许为了让表好看而放宽判据** —— 表短不是问题，表假才是
- ⛔ 判不了的事就说判不了，不许猜

# 报告格式
