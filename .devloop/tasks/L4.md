# 任务

## 背景

`devloop dispatch --tools implement` 是**写操作路径**：每单开一个独立 worktree，工人干完后强制跑接入项目自己的 `.devloop/gates.sh` 做验收。派单前，`devloop/cli.py::cmd_dispatch` 会先读一次闸文件算指纹（防篡改第 2 道）。

`devloop/config.py::ProjectPaths` 在构造时只检查 `.devloop/` **目录**存在，**不检查 `gates.sh` 文件存在**。于是当一个接入项目的 `.devloop/` 里只有 `rules-digest.md`、没有 `gates.sh` 时，指纹那一步抛出**未捕获的 `FileNotFoundError`**，用户看到的是一屏 Python 栈回溯。

有意思的是：`devloop/gates.py::run_gates` 自己**是**处理了这个情况的（它会返回一个「闸自身故障」的结果），但那段代码根本走不到——调用方先崩了。

## 要做的事

1. **让这个场景不再抛 Python 栈回溯**，改成一条人能看懂、点得出是哪个文件缺了的信息（信息里要出现 `gates.sh` 这个名字）。
2. **退出码必须符合本项目的约定。** 约定写在规则摘要的铁律 2 和 `devloop/cli.py` 顶部的模块 docstring 里——自己去读，别猜。「缺 gates.sh」属于哪一类失败，由你判断，但你的判断要经得起那条约定的检验。
3. **复现命令只覆盖了 `dispatch` 一个入口。** 算指纹那个函数在别的子命令里也被调用。自己 `grep` 一遍，别只修看得见的那处——本项目吃过好几次「实现了 ≠ 接上了」的亏。
4. **`--tools readonly` 的只读任务本来就不跑闸**，它的行为一个字都不能变：缺 `gates.sh` 不该挡住只读派单。
5. **`gates.sh` 存在时的原有行为不能变**（照常算指纹、照常派单）。

6. 按本项目风格给新增代码写**中文注释**，写清**为什么**这么处理，而不是复述代码在干什么。

# 禁令

- ⛔ **不许改 `tests/` 下的任何文件，也不许在 `tests/` 下新建文件。** 闸会拦下来。改判定标准不算通过。
- ⛔ **不许改 worktree 里的 `.devloop/`**——包括「为了复现方便，先把 `gates.sh` 删了/改名」。要复现就用上面命令造的临时项目。闸会拦。
- ⛔ **不许把 `--project` 指向本 worktree、也不许指向 DevLoop 主仓库。** 只能指向复现命令里那个临时项目。理由：`dispatch` 会在目标项目旁边建分支和嵌套 worktree，指错了会污染共享仓库，而且那是**你清理不掉**的东西。
- ⛔ **只改 `devloop/` 下的 `.py` 文件，且不得在 worktree 里留下任何新文件。** 不要动 `.md` 文档、`pyproject.toml`、`.gitignore`。
  临时脚本一律用 heredoc 直接跑（不落盘），或写进系统临时目录——**验收会看 `git status --porcelain`，未跟踪的散落文件同样算越界**。
- ⛔ **不许 `git add` / `git commit` / `git stash`**，把改动原样留在工作区。
- ⛔ 复现与自测时必须保留 `DEVLOOP_CLAUDE_BIN` 指向一个不存在的路径（复现命令里已经带上了）。**不要真的把单派出去。**
- ⛔ 不许把任何密钥、token 打进新增的日志或错误信息里。
