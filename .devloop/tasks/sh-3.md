# 角色

你是 DevLoop 这个 Python 工具包的维护者。你在一个基于干净检出的独立
git worktree 里干活，改动完成后会有一组闸自动裁决。

# 任务

**把一条代用品判据换成真判据。**

`tests/test_skip_gate_after_worker_killed.py` 里有一条
`test_跳过闸时台账记null不是零`，它的判据是：

> **`_run_unit` 的源码文本里不许出现某个字面值**

⛔ 这不是在守行为，是在守**措辞**。实测（2026-08-16）：
有人在**注释里**写了那几个字，它当场变红 —— **假红**，
而代码行为一个字节都没变。

⚠️ **假红比假绿贵**：假绿只损失一个 bug；假红让人去修一个不存在的东西，
修的办法还是「改注释绕开它」—— 那是**给判据让路**，不是判据在守东西。

**改成落在行为上的判据**：造一单「工人被死线打死 ⇒ 闸没跑」的场景，
真跑 `_run_unit`，然后**读台账那一行**，断言闸那一格是 `null`（不知道），
⛔ 不是 `0`（跑了且全过）。

⭐ 「不知道」与「零」是两件事 —— 这个项目为这个区分栽过多次。

# 改动范围

- `tests/test_skip_gate_after_worker_killed.py`（⭐ 本单**允许**改这一个已有测试文件）

⚠️ 同文件里其它几条测试**不许动**，它们守的是别的东西。

# 自己验

- `python -m pytest -q tests/test_skip_gate_after_worker_killed.py`
- `python -m pytest -q`
- ⭐ **红检**：把 `_run_unit` 里那处改成「闸没跑也记 0」，确认你的新判据变红；
  还原，确认回绿。两次输出都贴。
- ⭐ **反向绿检**：在 `_run_unit` 的注释里写上那个字面值，
  确认**新判据不会因此变红**（那正是旧判据的毛病）。
