# 任务

**写一份任务书模板：`templates/task.md`。**

新项目接入 DevLoop 时要照它写自己的任务书。现在这份模板不存在，
SPEC 的交付物清单里它一直标着缺口。

## 先取证，再动手

1. 读 `SPEC.md` 里关于任务书契约的那一节（搜 `# 角色`、`# 任务`、`# 禁令`），
   把**四段固定标题**和每段的要求抄准。
2. 读 `devloop/models.py` 的 `TaskSpec.load` ——它**真正校验**的是哪几段？
   ⚠️ 以代码为准：文档说的和代码校验的若有出入，**照代码写，并在模板里注明这个出入**。
3. 读 `.devloop/tasks/` 下现有的真实任务书（L3.md、L4.md），看真实的写法长什么样。

## 模板要包含什么

- 四段固定标题，每段下面用注释说清**这一段要写什么、为什么**
- 每段给一个填空式的示例（用 `<...>` 占位）
- ⭐ **必须写进去的一条**：验收标准要写成**机器能裁决的**形式。
  模型自述「我做完了」不是验收标准——这是这个项目的第一铁律。
- 一段「常见写坏的方式」，至少三条，每条说清为什么坏

## 判据

模板要能让一个**没读过这个项目**的人照着写出一份合格任务书。
写完之后，拿 `.devloop/tasks/L4.md` 对照检查一遍：它符合你写的模板吗？
不符合的地方，是模板错了还是 L4 错了？在报告里说清楚。

# 禁令

- ⛔ **只许新建 `templates/task.md` 这一个文件。** 不许改任何现有文件。
- ⛔ 不许改 `tests/` 下的任何东西。
- ⛔ 不许改 `.devloop/` 下的任何东西——那是本项目的规则与闸，改它会被闸判死。
- ⛔ 不许运行 `git commit` / `git push`。产出由编排方在跑完闸之后代为固化。
- ⛔ 判不了的事就说判不了，不许猜。

# 报告格式

最后输出一段，包含：

1. 新建了哪个文件，多少行
2. 你从哪几处取的证（文件:行号）
3. L4.md 对照的结果：符合 / 不符合的地方各是什么，你判断是谁的问题
4. 你**没能确定**的事情（如果有）
