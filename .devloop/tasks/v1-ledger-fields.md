# 任务

`devloop/telemetry.py::summarize(rows)` 把台账汇总成一段给人看的文字
（`devloop stats` 印的就是它）。

2026-08-02 台账新加了一个字段 `gate_code`：闸的**结构化**判定，
`0` 全过 · `1` 有未过（活没干好）· `2` 闸自身故障 · `null` 没跑闸。

⛔ 而 `summarize` 现在**一个字都没提它**。于是 `devloop stats` 看不出
「这批里有几单是闸自己坏了」——而那一档的处置（先修环境）与
「活没干好」（重试有意义）完全不同。

**给 `summarize` 加一行输出**，形如：

```
闸判定：全过 12 · 有未过 3 · ⚠️ 闸自身故障 1 · 没跑闸 4
```

要求：

- ⛔ **计数只认 `gate_code`，不许从 `gate_detail` 的文字里猜**。
  ⚠️ 那段文字里可能出现「闸自身故障」四个字而 `gate_code` 是 1
  （闸把失败的测试名原样放进说明里，而测试名可能含这四个字——
  2026-08-02 实测发生过）。
- ⛔ **历史行没有 `gate_code` 这个键**（该字段是新加的）。
  缺键的行要单独计一档「⚠️ 无判定记录 N」，**不许当成 `null`（没跑闸）**：
  「这一行是老的」与「这一单没跑闸」是两件事。
- 全是老行时那一行照常打印（`无判定记录 N`），⛔ 不许整行省略——
  省略会让人以为「没有闸判定这回事」。
- ⛔ 不许改 `summarize` 现有任何一行输出的措辞或顺序，只**加**一行。
- ⛔ 不许改 `telemetry.record` 或台账的任何字段。

**新建** `tests/test_summarize_gate_code.py`，至少 5 条测试：

1. 四种 `gate_code`（0/1/2/None）各计数正确
2. **缺键**的行落进「无判定记录」，不落进「没跑闸」
3. `gate_detail` 里含「闸自身故障」但 `gate_code == 1` → 计进「有未过」，
   ⛔ 不许计进「闸自身故障」（这条是本单的重点）
4. 全是老行时那一行仍然打印
5. 现有输出没被改动（拿一组 rows 比对改动前后除新增行之外逐字相同）
